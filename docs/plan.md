# Phone-Linux 実装計画（Termux 土台版）

2026-11-15 版。Termux 上で Claude Code を proot なしで直接動かす実験に成功したことを受け、Ubuntu(proot) を土台にする前の計画から切り替えた。

## 目的とスコープ

**目的**: Galaxy に入れるだけで Linux と Claude Code が速く動き、Galaxy 本体の設定を触らずに PC のキーボードで日本語が打て、Claude がスマホのアプリを操作できる、自分専用の端末アプリを作る。

**完了条件**
1. アプリを入れて開くと、初回セットアップのあと `claude` が proot なしで起動し、ログインして作業できる。
2. 標準キーボードが Samsung のままでも、マルチコントロール経由の PC キーボードで、半角/全角による日本語/英語の切替、ローマ字→かな、Ctrl+C が効く。配列は JIS と US から選べる。
3. ショートカットは PC の端末アプリと同じ割り当てが初期値で、設定画面から変えられる。
4. 背景（画像・単色・透明度）、配色、フォント、キー列を設定画面から変えられる。
5. Claude が MCP の道具で、スマホの画面を読み、撮り、タップ・入力し、アプリや URL を開ける。
6. スマホ操作の API を持ち、相手ごとに鍵（API キー）を発行・取り消しできる。
7. `claude remote-control` をボタン1つで常駐させ、PC から操作できる。
8. 画像を Claude への指示に入れられる（写真から選ぶ・今の画面を撮る・コピーした画像・他のアプリからの共有）。

**非スコープ**: Play ストア配布、Galaxy 以外の端末、公式 Termux との同時インストール、Termux の付属アプリ（Termux:API・Tasker・Widget・Float）、GUI デスクトップ。

**規模**: 大（Termux のフォーク＋入力処理＋スマホ操作サービス＋API）。

## 前提と制約

- 対象は Galaxy SM-S938Q（Android 17、arm64）。入れ方は `adb install`（ADB で入れるアプリは Android の開発者認証の対象外）。
- 土台は termux-app（GPLv3）のフォーク。リポジトリは非公開のまま個人で使う。
- `targetSdk 28` を維持する（アプリのデータ置き場のプログラムを実行するため）。
- 公式 Termux と署名が違うので、入れる前に公式 Termux を削除する必要がある。削除すると Termux の中身（`$HOME` など）が消えるため、先に `/sdcard` へ退避する。

## 現状把握（実験で確かめたこと）

- Claude Code（公式 linux-arm64・glibc 版）は、`glibc-runner` の起動部品 `ld-linux-aarch64.so.1` で直接起動できる。ログイン・通信・git・Python まで通った。
- `grun` は空白を含む引数を壊すので使わない。自前の起動口 `claude-native` を使う。
- Termux の `termux-exec`（`LD_PRELOAD`）は、Claude 本体からは外し、Claude が使うシェル（`claude-shell`）にだけ付け直す。どちらかを怠ると起動に失敗する。
- `/tmp` は使えないが、`TMPDIR=$PREFIX/tmp` で Claude 側が回避する。
- 速さ: 1500 ファイルの git 作業で、直接 0.32 秒、proot の Ubuntu 3.27 秒（約10倍）。
- Termux の bootstrap 作成スクリプト（`generate-bootstraps.sh`）には、道具を追加で詰め込む仕組みがある（`ADDITIONAL_PACKAGES`）。
- 詳細は kb `recipes/20261115-termux-claude-code-proot-glibc`。

## 設計方針

### 判断1: 内部 ID は `com.termux` のまま、中身を作り込む（採用）
- 内部 ID を変えると、Termux の全パッケージの作り直しが必要になる。そのままなら、公式の配布元（`pkg install`）をそのまま使える。
- ホーム画面のアプリ名（Phone-Linux）とアイコンは自由に変える。
- 代わりに、公式 Termux とは同時に入れられない（入れ替える）。

### 判断2: Claude Code は glibc で直接動かし、Ubuntu は予備に回す（採用）
- 普段は `claude-native` で動かす。普通の Linux が必要な作業のときだけ、proot の Ubuntu を使えるようにしておく。
- Claude Code の本体の入手と更新は自前の仕組みで行う（公式の install.sh は Android を対象にしていないため）。候補は2つ: npm で Linux 用の部品を指定して取る方法と、公式の配布元から直接取る方法。段階1の最初に、実機で動く方を選ぶ。

### 判断3: 入力・見た目・ショートカットはアプリ内で完結させる（採用）
- 物理キーは、端末画面（`TerminalView`）が本体のキーボードより先に受け取る。半角/全角（`KEY_GRAVE` の押しっぱなし）の判定と、ローマ字→かな変換はアプリ内で行う。
- 配列（JIS / US）は、アプリが自分で読み替える。Galaxy の物理キーボード設定には頼らない。
- ショートカット・配色・背景・キー列は、1つの設定ファイルにまとめ、設定画面から編集できるようにする。

### 判断4: スマホ操作は「ユーザー補助サービス」＋「鍵つきの API」＋「MCP」（採用）
- アプリにユーザー補助サービス（AccessibilityService）を持たせ、画面の読み取り・撮影・タップ・入力・戻る操作を行う。アプリや URL を開くのは Intent で行う。ワイヤレスデバッグは使わない。
- 操作はアプリ内の API として出す。受け付けるのはスマホの中から（`127.0.0.1`）だけ。PC からは adb の転送か Tailscale を経由する。
- 鍵（API キー）は設定画面で発行・取り消しする。鍵ごとに、名前・使える操作・有効期限を決められる。
- Claude からは、この API を包んだ MCP サーバー（`phone_screenshot`・`phone_ui_tree`・`phone_tap`・`phone_type`・`phone_open` など）として使う。
- 支払い・削除・送信など取り返しのつかない操作は、スマホ側で確認を出す。操作の記録を残す。

### 判断5: 使わない機能は外す
外すもの: 外部からのコマンド実行（`RunCommandService`）、ほかのアプリへのファイル提供（DocumentsProvider）、付属アプリ用の設定。ファイル受け取り（`FileReceiverActivity`）は外さず、判断7の画像の入口に作り変える。ログイン用 URL などは、`xdg-open` を `termux-open-url` につなぐ。

### 判断7: 画像は「ファイルに置いて、その場所を入力欄に入れる」（採用）
- Claude Code は、指示に書かれた画像ファイルの場所を読めば画像を理解できる。端末からクリップボードの画像を直接渡す方法は Android では使えないため、この形にそろえる。
- 入口は4つ: 写真から選ぶ（Android の写真選択画面）、今の画面を撮る（判断4のユーザー補助サービス）、コピーした画像（クリップボード）、他のアプリからの共有（`FileReceiverActivity` を作り変える）。
- どの入口も、画像を `~/inbox/` に保存し、入力欄に `[画像 N]`（中身はファイルの場所）を差し込む。古い画像は一定期間で消す。
- 端末の画面に縮小した画像を出すのは任意（terminal-emulator には画像表示の部品 `TerminalSixel` がある）。

### 判断6: リポジトリの構成
termux-app を、このリポジトリの `app/` に subtree として取り込む。GitHub のフォーク機能は、公開リポジトリのフォークを非公開にできないため使わない。

## 実装ステップ

### 段階0: フォークを作って入れ替える
- **目的**: 自分でビルドした Termux が、公式の代わりに Galaxy で動く。
- **変更対象**: `app/`（termux-app を取り込む）、署名の設定（鍵はリポジトリの外に置く）、アプリ名・アイコン。
- **具体的な変更**: termux-app を subtree で取り込み、Windows で `gradlew assembleDebug` を通す。今の Termux の `$HOME` を `/sdcard` に退避してから、公式 Termux を削除し、自作版を入れる。
- **完了条件・検証**: ホーム画面に Phone-Linux が出る。`pkg install` が公式の配布元から通る。退避した `$HOME` を戻せる。
- **依存**: なし。

### 段階1: Claude Code が最初から動く
- **目的**: 初回セットアップだけで、`claude` が proot なしで使える。
- **変更対象**: 自作の bootstrap（`ADDITIONAL_PACKAGES` に git・ripgrep・python・glibc-repo・glibc-runner・android-tools）、`claude-native`・`claude-shell`・`claude-update` を入れる初回スクリプト。
- **具体的な変更**: termux-packages の `generate-bootstraps.sh` で、公式の配布元から bootstrap を作る（作り直しは不要）。Claude Code の入手と更新の方法を決めて組み込む。
- **完了条件・検証**: アプリを入れ直した直後に、`claude --version`・ログイン・`claude -p` で git の作業まで通る。`claude-update` で新しい版に上がる。
- **依存**: 段階0。

### 段階2: 入力・ショートカット・見た目
- **目的**: 完了条件2〜4。
- **変更対象**: `TerminalView` まわり（物理キーの振り分け、ローマ字→かな、配列の読み替え）、設定ファイルと設定画面、背景・配色・フォントの描画。
- **具体的な変更**: 記録済みのキーの並び（半角/全角の押しっぱなし）を使った判定。JIS/US の切替。PC と同じショートカットの初期値と、その編集画面。背景画像・透明度・配色の設定。
- **完了条件・検証**: 単体テスト（キーの並び→切替は1回だけ、`kya`→「きゃ」、JIS の `@` の位置）。実機で、標準キーボードを Samsung のままにして、マルチコントロールから日本語入力・Ctrl+C・ショートカットが効く。
- **依存**: 段階0（段階1と並行できる）。

### 段階2.5: 画像を入れる
- **目的**: 完了条件8。
- **変更対象**: 画像の入口（写真選択・クリップボード・共有の受け取り）、`~/inbox/` の管理、入力欄への差し込み、キー列とメニューの「画像」ボタン。
- **具体的な変更**: 3つの入口から画像を `~/inbox/` に保存し、入力欄に場所を差し込む。今の画面を撮る入口は、段階3のユーザー補助サービスができてからつなぐ。
- **完了条件・検証**: 写真・コピーした画像・共有の3通りで画像を入れ、Claude が中身を説明できる。古い画像が期限で消える。
- **依存**: 段階0・段階1。

### 段階3: スマホ操作・API・MCP
- **目的**: 完了条件5・6（と、完了条件8の「今の画面を撮る」）。
- **変更対象**: ユーザー補助サービス、API の受け口、鍵の発行画面、MCP サーバー、操作の記録。
- **具体的な変更**: 画面の読み取り・撮影・タップ・入力・アプリを開く操作を API にする。鍵の発行と取り消し、使える範囲の設定。MCP サーバーを Claude の設定に登録する。
- **完了条件・検証**: Claude に「設定アプリを開いて Wi-Fi の画面を撮って」と頼み、画面が撮れる。鍵の無い呼び出しと、取り消した鍵が拒否される。重要な操作で確認が出る。
- **依存**: 段階0。

### 段階4: 連携と仕上げ
- **目的**: 完了条件7と、使い続けられる状態。
- **変更対象**: Remote Control の常駐サービス、`pc/sync_to_phone.py`（送り先を Termux の `$HOME/.claude` に変える）、README・architecture.md。
- **具体的な変更**: ボタン1つで `claude remote-control` を常駐させる。ハーネス転送をこのアプリの置き場所に合わせる。Ubuntu 用のファイル（`phone/`）は、予備として残すか削除するかを決める。
- **完了条件・検証**: PC の claude.ai/code に Galaxy が出て操作できる。転送後に、スマホの Claude がハーネスのルールで答える。
- **依存**: 段階1〜3。

## リスクと未確定事項

| リスク | 影響 | 緩和策 |
|---|---|---|
| 公式 Termux を削除すると中身が消える | 今の環境を失う | 段階0の前に `$HOME` を `/sdcard` に退避し、戻せることを確かめる |
| Claude Code の更新で glibc 直接起動が動かなくなる | Claude が使えない | 版を固定して更新する仕組みにし、動かなければ前の版に戻す。予備に proot の Ubuntu を残す |
| Claude Code 本体の入手方法が公式に用意されていない | 段階1が止まる | 段階1の最初に2つの候補を実機で確かめる |
| `targetSdk 28` が将来の Android で入れられなくなる | 更新後に入らない | Android の更新ごとに確かめる（Termux 本家も同じ立場） |
| ユーザー補助サービスは強い権限 | 誤操作・悪用 | 鍵つき・スマホ内だけの受け口・重要操作の確認・操作の記録 |
| Termux 本家の更新を取り込む手間 | 古いまま取り残される | 変更を `TerminalView` と追加部品に寄せ、本家の部分はなるべく触らない |

**要確認**: 「API の発行」は、スマホ操作 API の鍵を発行する意味と解釈した（Anthropic の API キーの発行ではない）。

## 検証計画

- **単体テスト**: キーの判定（記録したキーの並び）、ローマ字→かな、配列の読み替え、鍵の検証。
- **実機テスト**: USB の adb で入れて確かめる。キー入力は getevent の記録と画面撮影で、スマホ操作は Claude に実際の作業を頼んで確かめる。
- **段階ごと**: 各段階の完了条件を、毎回アプリの入れ直しから通しで確かめる。
